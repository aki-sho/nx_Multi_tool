# NX Multi Tool

NexaPressの管理画面に、サイト運営・コンテンツ管理・日常作業の13種類の道具をまとめる拡張機能です。WP Helpers Multiの機能構成を参考に、NexaPressのルーター・権限・フック・投稿形式へ移植しています。

- 拡張ID／フォルダ名：`nx_Multi_tool`
- 表示名：**NX Multi Tool**
- バージョン：1.0.1
- 対応CMS：NexaPress 2.4.0以上
- PHP：8.0以上。PDO MySQL、DOM、mbstring、cURL。ZIP導入・ビルドにはZipArchiveが必要です。

## インストール

1. `php build.php` で `dist/nx_Multi_tool-1.0.1.zip` を作成します。
2. NexaPress管理画面の「拡張機能」からZIPをアップロードし、有効化します。
3. 拡張機能メニューの「Multi Tool」を開きます。
4. 使う機能を選択し、設定を保存します。初期状態では13ツールが有効です。
5. URL収集を使う場合は、ダッシュボードで公開サイトURLを設定します。
6. コメントを受け付ける場合は「公開記事・固定ページでコメントを受け付ける」をオンにします。受付は初期状態では停止しています。

本体・テーマのファイル変更は不要です。管理操作はすべて `extensions.manage` 権限を要求します。本体の標準権限では管理者が対象です。機能をオフにすると、画面・APIへの直接アクセスも停止します。

## 機能一覧

| ツール | 内容 |
|---|---|
| サイトリンク | 制作・構築・運用・広告等のカテゴリ別サービス集。キーワードで絞り込み |
| QRコード | ブラウザ内で生成。サイズ・余白・誤り訂正・PNG保存。入力の外部送信なし |
| 電卓 | 四則演算・小数・演算順序・キーボード入力 |
| bcrypt | ハッシュ生成・照合・コピー。通常cost 10〜12、明示した検証モードで4〜9 |
| パスワード生成 | 4〜64文字、1〜8個、英大小文字・数字・記号、プリセット、コピー |
| タイマー | カウントダウン、ストップウォッチ、ラップ、アラーム、通知音、ブラウザ通知、リロード復元 |
| リンク点検 | 保存済み本文にある指定URL文字列・ドメイン誤記候補をバッチ点検。自動修正なし |
| アクセスログ | 日時・HTTP・IP・URL・参照元・UA、検索、日付範囲、CSV、選択／期間／全削除、期限付きIP拒否 |
| セキュリティチェック | 設定・環境・既存ログを読み取り、10項目の確認範囲と理由を表示。再チェック |
| 投稿データ | 投稿／固定ページの情報、画像・リンク・文字数、保持ログ内の閲覧数。項目選択、絞り込み、ソート、CSV |
| サイト内URL一覧 | 記事以外の参照URLを収集。HTTP・発見元・アクセス条件、検索、ソート、種類の除外／限定、CSV、停止／再開 |
| 記事検索・置換 | 編集中の本文を文字列／正規表現検索。強調表示、前後移動、個別／一括置換、取り消し |
| コメント管理 | 拡張独自の承認制コメント、検索、承認待ち／承認済み／スパム／ゴミ箱、対象確認付きIP拒否 |

ダッシュボードは「コンテンツ」「サイト管理」「ユーティリティ」の3分類です。共通の文字サイズを5段階で変更できます。

## NexaPress向けの調整

- WordPressのAPI・投稿メタ・Gutenberg・WP-Cronは使用しません。投稿・固定ページはNexaPressのテーブルとURL設定を参照します。
- 投稿データのカテゴリは本体と同じ単一階層です。説明文はNX Head Settingsの個別設定がある場合は参照し、それ以外は抜粋を表示します。基本情報の並び替えは全検索対象へ適用し、項目の表示選択をCSVにも反映します。
- 閲覧数は保持しているGET・HTTP 200のログから集計した参考値です。保持日数・記録頻度・キャッシュの影響を受け、累積PVやリアルタイム解析とは異なります。
- リンク点検はCMSの保存済み本文を直接走査します。サイトマップを起点とする必要がありません。リンク先の全件HTTP到達確認やリンクの自動変更は行いません。
- セキュリティチェックはローカルにある情報だけを使います。WordPress公式の更新API、脆弱性DB、外部診断サービスへの照会はありません。確認できない耐性は「未確認」です。攻撃の実行・自動修正はありません。
- 配布先は `aki-sho/nx_Multi_tool` です。本体2.4.1の拡張カタログへ登録し、GitHub Releasesからの導入・更新に対応します。

## コメントとIP拒否

本体にコメント機能がないため、独立したテーブルと受付経路を用意しています。全件承認制・プレーンテキスト表示です。メールアドレスと送信元IPは管理画面だけに表示します。10分間に同じIPから5件、合計100,000件を上限とします。

公開記事・固定ページの描画時に `nx_head` フックからフォームを追加します。標準のdefault／monoedgeテーマのように `nx_head()` と `main` または `article` を使用するテーマが対象です。カスタムテーマではこのフックと配置先が必要です。下書き・プレビュー・削除済み記事では受け付けません。

フォームは同一サイトのiframe内で、CSRFトークンを含む応答を `no-store` で取得します。公開ページのキャッシュにトークンを書き込みません。コメントの公開状態変更も、次回のフォーム取得に反映されます。

IP拒否はアクセスログとコメント管理で共有します。拒否期限・許可IPは共通設定で変更でき、自分の現在のIPは新たに拒否できません。拒否は公開ページとコメント投稿へ適用し、管理画面のログイン制限は既存のAccess Guardに任せます。スパム指定だけではIPを拒否しません。「スパム＋IP拒否」には対象確認画面があります。

接続元IPには `REMOTE_ADDR` を使います。転送ヘッダーは信頼しません。リバースプロキシ環境ではWebサーバー側で信頼するプロキシを設定し、正しい接続元IPを渡してください。

## URL収集

保存本文・公開ページ・XMLサイトマップ・CSS・JSONから、設定したサイトのURLを発見します。投稿・固定ページもリンク発見には使いますが、それ自体のURLは結果から除外します。JavaScript実行後だけに現れる参照先や、未リンクのURLをすべて列挙するものではありません。

- 同じオリジン・同じ設置先パス配下の公開HTTP/HTTPSだけを取得。ポートは80／443。
- 内部・予約IPを拒否し、DNS解決結果をcURLへ固定。転送先にも同じ条件を適用。
- 管理・ログイン・この拡張のURLと、クエリ付きURLは巡回しません。クエリ値は数値の限定項目以外を伏字にします。
- 最大10,000候補・2,000回の通信。応答は1MiB、1通信8秒、転送は3段まで。
- 取得用の名前解決はOSのDNS設定を使用します。DNS解決自体の待ち時間はOSに依存します。
- 画像・一般的なバイナリはHEADのみ。HEAD非対応時は最大512バイトのRange GETを試します。
- 収集結果はページを離れると削除要求を送信し、同じ画面での停止・検索・ソートでは維持します。結果の有効期限は1時間、同じ管理者の直近の収集だけを保持します。
- アップロード配下・画像への転送・添付ページ形式の除外／限定は即時反映し、選択はブラウザに保存します。NexaPress本体にはWordPress形式の添付ページはありませんが、対応する形式のURLを発見した場合は分類できます。

ローカルホスト・LANだけのCMSでは、内部IP制限によりHTTP巡回は実行できません。記事本文からのURL抽出は実行できます。

## 本文の検索・置換

投稿・固定ページの新規作成と編集画面にパネルを追加します。標準テキストエリアとNexaPress Classic Editorに対応します。HTMLのタグ・属性・コード部分を保護し、置換文字列をHTMLとして実行しません。

検索対象は本文200万文字・一致5000件まで。正規表現は独立Workerで実行し、1.5秒で中止します。空文字に一致する式は使用できません。置換履歴は現在の画面内で20回まで保持し、その後の手動編集がある場合は古い内容への上書き復元を停止します。保存・公開はCMSの標準ボタンで行います。

Classic Editor自身の許可タグや保存時の安全化規則は引き続き適用されます。例えば現行Classic Editorがビジュアル表示で除去したタグは、検索パネルから復元できません。

## 保存先と削除

- 設定・IP拒否・一時収集：`storage/extensions/nx_Multi_tool/`
- DBテーブル：`{本体の接頭辞}nxmt_logs`、`{本体の接頭辞}nxmt_comments`
- DBテーブルは必要になった時点で作成します。本体の投稿・ユーザーテーブルの構造は変更しません。
- 拡張の更新・無効化・削除では上記の設定とDBを自動削除しません。バックアップ後に管理してください。
- Webサーバーは `storage` を非公開にしてください。Apache向けの拒否設定も拡張の保存先に作成します。

設定JSONはファイルロックと同一ディレクトリの一時ファイルへの書込み・置換で保存します。破損した設定を上書きせずエラーにします。管理APIは権限・機能の有効状態・CSRFを確認します。

## 構成

```text
nx_Multi_tool/
├── manifest.json / bootstrap.php / autoload.php
├── src/                  共通処理・各ツールのサービスとコントローラー
├── admin/dashboard.php   CMSに組み込む入口
├── views/tools/          13ツールの管理画面
├── assets/               CSS・JavaScript・QRライブラリ・通知音
├── config/site-links.php サービス一覧
├── build.php             ZIP作成・内容照合
└── tests/                隔離した回帰テスト（配布対象外）
```

## 開発時の確認

```powershell
python tests/run.py
php -d display_errors=0 -S 127.0.0.1:18741 tests/router.php
# 別の端末で
node tests/browser.cjs
php build.php
```

PHPのPDO SQLite拡張、Python 3、Node.js 22以上、ChromeまたはEdgeをテストに使用します。`NXMT_CHROME` でブラウザの実行ファイルを変更できます。本体は同階層の `nexapress`、エディターは `nexapress-classic-editor` を参照します。テスト用コピー・SQLite DB・セッション・ブラウザプロファイルは `tests/.runtime/` 内だけに作成し、実CMSの設定・DBを変更しません。

ブラウザ検証は独立したプロファイルでローカルのテストサイトだけを開きます。テスト用ログインルートは配布ZIPに含めません。MySQL/MariaDBと公開サーバーへの最終導入確認は別途行ってください。

## 1.0.1の改修

- URLの種類、元のHTTP結果、最終取得結果、転送先、要確認の絞り込みを追加しました。公開CSS・画像の取得成功を危険と判定しません。
- robots.txt・sitemap.xmlの自動候補と、実際に発見したリンクを区別します。候補の404・HTML応答を通常のリンク切れと分けて表示します。
- ログイン画面への転送や、HTTP 200の認証フォームを「元ページが閲覧できる」と判定しません。管理・認証・内部領域は取得せず、外部への転送も追跡しません。
- アイキャッチはCMSのメディア参照を使用します。srcset、poster、埋め込みCSS、引用符だけのCSS import、エスケープされたJSON URLも収集します。
- 収集中は変更行だけを返し、全件の再転送を抑えます。CSVは現在の絞り込み・並び順・追加列を反映します。

追加の確認は `php tests/http-client.php` で行えます。HTTP/DNSはテスト内の代替関数を使い、外部へ通信しません。`tests/apache-verification.py` はローカルの専用MariaDBとApacheを使うWindows/XAMPP向けの任意テストです。`tests/task-services.py` で専用サービスを開始し、終了時は `.work/services.stop` を作成します。実際のCMSのDBは使用しません。
